Start hereHow to study Rust on paper

Rust is a language you learn by arguing with its compiler. This book lets you have that argument with a pencil. Every chapter shows real code, the exact error the compiler prints, and the fix, so you can practise reading and reasoning the way you will at a keyboard.

The four questions

Ask these of every line you read. Most Rust bugs and most compiler errors are an answer you got wrong.

  1. Who owns this value? Exactly one variable does.
  2. Is it moved, copied or borrowed here?
  3. How long does each borrow live? Draw it as a bar next to the code.
  4. What can fail, and where is it handled?
Tip

Keep a notebook page called Error diary. Each time a chapter shows a compiler error, write its code (like E0382), one line on the cause and one line on the fix. By Part 5 you will have your own index of the errors you will meet most.

The box types

Worked boxes trace code step by step. rustc says boxes print real compiler output. Tip and Pitfall boxes are habits worth keeping. Exercises end each chapter, with answers under the dashed line: cover them with a card until you have tried.

Chapter 3Ownership and moves

Every value has one owner, the variable that holds it. When the owner goes out of scope, Rust frees the value. Assigning a heap value like a String to another variable, or passing it to a function, moves it: the new variable is the owner and the old one can no longer be used.

Worked: trace a move
fn main() {
    let a = String::from("ore"); // a owns the buffer
    let b = a;                   // moved: b owns it
    println!("{b}");             // fine
    println!("{a}");             // error: a was moved
}

rustc says
error[E0382]: borrow of moved value: `a`
  |  let a = String::from("ore");
  |      - move occurs because `a` has type `String`,
  |        which does not implement the `Copy` trait
  |  let b = a;
  |          - value moved here

Fix it by borrowing (let b = &a;) or, only if you truly need two copies, let b = a.clone();

Pitfall: a borrow into a Vec, then a push
let mut v = vec![1, 2, 3];
let first = &v[0];
v.push(4);            // E0502: v is still borrowed
println!("{first}");

push may move the whole buffer to a bigger allocation, which would leave first pointing at freed memory. Copy the number out (let first = v[0];) or finish using first before you push.

Chapter 19Borrow checker clinic

Each case is a program a real learner writes in their first month. Read the broken code, predict the error before you read it, then compare your fix with the one given.

Case 3Returning a reference to a local
fn shout(text: &str) -> &str {
    let loud = text.to_uppercase();
    &loud          // E0515: loud dies at the brace
}

Diagnosis

loud is a new String owned by the function. A reference cannot outlive its owner, so there is nothing valid to point at after the function returns.

Fix

fn shout(text: &str) -> String {
    text.to_uppercase()  // hand the owner to the caller
}
Case 4Calling a &mut self method inside a loop over self
for item in &self.items {
    self.log(item);  // log(&mut self): E0502
}

Fix: borrow the fields, not the whole struct

let Self { items, log, .. } = self;
for item in items.iter() {
    log.push(format!("saw {item}"));
}

Inside one function Rust tracks borrows per field, so items and log can be borrowed together. A method call borrows all of self.

Tip: when references fight you, use indices

Trees with parent links and graphs are painful with references. Keep nodes in a Vec and link them by usize index: no lifetimes, no Rc<RefCell<_>>.

struct Node { val: i32, parent: Option<usize>, kids: Vec<usize> }
struct Tree { nodes: Vec<Node> }

Chapter 20Algorithms the Rust way

Worked: two sum, [2, 4, 9, 3] with target 7
fn two_sum(nums: &[i32], target: i32) -> Option<(usize, usize)> {
    let mut seen = HashMap::new(); // value -> index (std::collections)
    for (i, &n) in nums.iter().enumerate() {
        if let Some(&j) = seen.get(&(target - n)) {
            return Some((j, i));
        }
        seen.insert(n, i);
    }
    None
}

Problem 20.4

Write fn max_gap(v: &[i32]) -> Option<i32> that returns the largest difference between neighbours, using one iterator chain and no index variable.

Answer v.windows(2).map(|w| (w[1] - w[0]).abs()).max(). It returns None for fewer than two items, because windows(2) yields nothing.
